## 引子：一个用"沙箱"说不通的场景

第三十一章确认了行业事实：Codex、dsh 等端侧 Agent 用操作系统免费送的沙箱（Landlock/Seatbelt），云端企业用昂贵的 MicroVM。当时留下了一个没有展开的问题：**车载、机器人上的端侧模型——尤其是 2B 级别的小模型——需要什么样的沙箱？**

顺着这个问题往下想，会遇到一个奇怪的感受：把云端沙箱那套语言（隔离、逃逸、爆炸半径）套到端侧模型上，总觉得哪里不对劲。一个 2B 的小模型，跑在自己的车机上，给车主服务——它"逃逸"到哪里去？它连恶意都谈不上，它只是**经常错**。

本章论证：这种"说不通"不是语感问题，而是**沙箱这个概念本身存在一个未被命名的分界**。跨过这条线，沙箱的存在理由、威胁模型、设计中心、判据全部反转。这条线的两边，本章分别称为**关押型沙箱**与**监护型沙箱**。

## 一、分界的发现：保护对象反转

先看两个场景的原始对照：

**场景 A（云端大模型）**：一个多租户平台，运行用户提交的、由大模型生成的代码。威胁来自：提示词注入让模型生成恶意代码、模型幻觉生成破坏性命令。沙箱的任务：**即使代码是恶意的，也伤不到宿主和其他租户。**

**场景 B（车载/机器人端侧小模型）**：一颗车规芯片上的 2B 模型，给车主生成车机自动化脚本、给机器人输出关节控制。它没有"其他租户"，它服务的对象就是这辆车、这个家。威胁来自：**模型能力不足，常态性地输出错误动作。** 沙箱的任务：即使它每次都想好好干，也不能让它把车开进沟里。

把两个场景的要素并置：

| | 场景 A（云端） | 场景 B（端侧） |
|---|---|---|
| Agent 的善恶假设 | **可能恶意**（注入后必然恶意） | **善意但无能**（弱模型，常态出错） |
| 危险的来源 | 攻击者的意图 | 模型的能力边界 |
| 保护对象 | **环境**：宿主、其他租户、外部世界 | **Agent 服务的对象**：任务本身、人、物理世界 |
| 失败的性质 | 攻击成功 = 越权 | 犯错 = 蠢死 |
| 后果的可逆性 | 中（kill 重来，损失是钱） | **低（物理后果没有 rollback）** |

**核心观察：保护对象反转了。** 场景 A 里，Agent 是危险源，世界是受害者，隔离方向是"把 Agent 关起来"；场景 B 里，Agent 是服务者，它的无能是风险，隔离方向是"约束它的每一次输出"。

这就是为什么"沙箱"一词在场景 B 里总觉得别扭：**沙箱的经典心智模型是"关押"——保护世界免受坏人；而场景 B 要的是"监护"——保护弱者不犯错。**

## 二、两种沙箱的正式定义

### 2.1 关押型沙箱（Confinement Sandbox）

**存在理由**：假设执行体可能是恶意的，限制其行为的爆炸半径。

- **威胁模型**：提示词注入、恶意代码、逃逸攻击——危险有"意图"；
- **保护对象**：宿主环境、其他租户、外部世界；
- **核心问题**："如果它想搞破坏，最多能破坏多大？"；
- **设计中心**：**隔离边界**——KVM 独立内核、网络策略、凭据注入、出口审计；
- **失败哲学**：fail-close——宁可拒绝，不放行未审计的行为。

本系列前二十四章讲的基本都是它：CubeSandbox 是关押型的工程极致，E2B、Firecracker、Kata 同属此列。它的全部机制都服务于一个目标：**把不可信的执行体圈在一堵墙里，墙内随便折腾，墙外毫发无伤。**

### 2.2 监护型沙箱（Guardianship Sandbox）

**存在理由**：假设执行体是善意的但能力不足，约束其每一次输出的后果，并管理错误的累积。

- **威胁模型**：幻觉、能力边界、分布外场景——危险没有意图，只有"不够好"；
- **保护对象**：Agent 自己的任务、它服务的人与物理世界；
- **核心问题**："如果它认真干活还是干错了，最坏后果是什么？错误会怎样累积？"；
- **设计中心**：**输出校验与兜底**——动作包络、速率限制、置信度降级、fail-safe 状态、错误累积追踪；
- **失败哲学**：fail-safe——出错时退到安全状态（交还人类、停车、悬停），而不是拒绝服务。

**一句话钉死分界**：

> **关押型沙箱问"它会不会害人"，监护型沙箱问"它会不会蠢死"。云端防恶意，端侧防愚蠢。**

### 2.3 为什么这个分界此前没有被明确命名

（推演）三个原因。其一，**历史上两类需求分属两个圈子**：关押型属于安全/基础设施圈（容器、虚拟化、云安全），监护型属于功能安全圈（ISO 26262、ASIL、机器人安全）——两个圈子用不同的语言（"逃逸/爆炸半径" vs "危害分析/安全状态"）讨论相似的结构，从未互相翻译。其二，**Agent 时代之前，"善意的无能执行体"不常见**——传统软件的错误由测试和 QA 在发布前消灭，运行时只剩恶意问题；弱模型的常态化错误是新鲜事物。其三，**大模型率先在云端爆发**，沙箱的叙事被云端场景垄断了三年，端侧 Agent（车载、机器人、IoT）到 2026 年才成气候。

第三十一章引用的行业事实可以佐证其三：端侧工具（Codex/dsh）目前用的是关押型的轻量版（OS 级沙箱），**监护型至今没有成熟产品**——零件散落在四个领域（见第六节），整机无人拼装。

## 三、分界的判据体系

关押型沙箱在本系列中已有一套判据（"砍掉它，60ms 变不变""爆炸半径多大"）。监护型需要一套自己的判据，本章提出四问：

```text
监护型四问：
Q1（包络）：单次输出的最坏后果被限制在多大？
    ——对应关押型的"爆炸半径"，但粒度从"整个沙箱"细化到"每个动作"

Q2（累积）：错误的累积会不会突破安全预算？
    ——单次合规 ≠ 安全。每次偏 1 度，三百次后偏出车道。
    监护型必须管理"错误的时间积分"，不只是单次幅度

Q3（降级）：置信度低时退到哪个安全状态？
    ——对应关押型的 fail-close，但方向相反：不是拒绝服务，
    而是退到"确定的低能力状态"（人类接管、靠边停车、悬停）

Q4（观测）：拦截和降级发生时，向谁报告、多快、带什么证据？
    ——错误是常态，所以每一次都要能复盘：为什么错、
    错在哪个分布外场景、下次训练要不要这个样本
```

**Q2 是两者最深刻的差异，值得单独展开**。关押型不需要考虑累积——一次攻击成功就失败了，防住每一次就等于防住了全部。监护型面对的是**连续犯错的执行体**：单次动作永远在包络内，但偏差会漂移、会共振、会在长任务里累积成灾难。因此监护型的核心数学不是"单次约束"而是**误差的时间积分管理**——这与传统功能安全"单次包络"的差异，正是 2026 年那篇《Scenario-Specific Safety Envelopes for Driving VLAs》（arXiv:2606.14238）提出"二维安全包络"的深层原因：VLA 的安全参数必须按场景和时间两个维度定义，单一聚合阈值在累积误差面前失效。

（推演）进一步：Q2 暗示监护型沙箱与**训练闭环**存在结构性连接——错误累积的数据正是模型迭代的养料。关押型沙箱的审计日志服务于取证与合规（事后查人），监护型沙箱的轨迹记录服务于**模型改进**（事后训练）。前者是法律档案，后者是病历。这可能是"沙箱成为 Agent 运行时"（第二十四章）在端侧的独有形态：**监护型沙箱天然长在训练回路里。**

## 四、车规级大模型：两种沙箱的叠加态

回到引子的问题：车规级大模型的沙箱怎么说？答案现在是精确的——**它不是一种沙箱，是两种沙箱的叠加，底下再垫一层传统功能安全**：

```text
车规级大模型 Agent 的完整安全栈：

┌──────────────────────────────────────┐
│ 监护层（监护型沙箱）                    │
│   模型输出 → 场景化动作包络检查          │
│   置信度低 → 降级（交还人类/靠边停车）    │
│   错误累积追踪 → 超阈值强制干预          │
│   防的是：蠢（幻觉、能力不足、分布外）    │
├──────────────────────────────────────┤
│ 关押层（关押型沙箱，轻量版）             │
│   模型生成的代码 → Landlock/受限令牌     │
│   OTA 更新、第三方插件 → 隔离执行        │
│   防的是：坏（注入、恶意代码）           │
├──────────────────────────────────────┤
│ 物理层（传统功能安全，几十年成熟）        │
│   硬编码包络 + 看门狗 + ASIL-D 认证     │
│   防的是：一切越界，不管来源            │
└──────────────────────────────────────┘
```

三层各防一种危险：**物理层防"任何越界"（最后一道闸），关押层防"恶意代码"，监护层防"AI 的愚蠢"。** 车规场景的独特性在于三层缺一不可——它的失败既有物理后果（要监护），又有攻击面（要关押），还必须过认证（要物理层兜底）。

用第五~七章的语言说：**关押层是本系列机制章在端侧的轻量移植，监护层是全新的物种**——它不隔离进程，不隔离文件，它隔离的是"错误在时间中的传播"。

## 五、分界在四层平面框架中的位置

把新分界放进第三十章建立的四层平面（继承/供给/治理/控制），会得到一个收束性的图景：

```text
关押型沙箱 = 供给语义发达 + 治理语义正常
             （拼 60ms 创建、5MB 密度、千级并发——沙箱要"造得快"）

监护型沙箱 = 供给语义退化 + 治理语义极端化
             （不需要快、不需要密——但治理从"网关层"下沉到"每一帧"）
```

**治理语义的频率与粒度差了三个数量级**：关押型的治理在出口网关（每次出站查一次），监护型的治理在每个控制周期（每 10~50ms 查一次）；关押型管的是"行为的合法性"，监护型管的是"数值的包络 + 误差的积分"。**这就是云端沙箱搬不到端侧的根本原因：不是技术搬不过去，是治理的频率、粒度、数学结构都不同——两个物种。**

（推演）这个图景还解释了第三十一章留下的一个悬案：为什么端侧工具（Codex/dsh）只用免费的 OS 沙箱就满足了——因为它们面对的是**关押型需求**（防自己 Agent 误删文件），而 OS 沙箱恰好是关押型的轻量实现。**端侧的监护型需求（防弱模型蠢死）至今无人供给**——这不是市场没有需求，是需求还没有被翻译成产品语言。

## 六、监护型沙箱的现状：零件齐全，整机空缺

按"零件成熟度"盘点监护型的四个组成部分（核对日期 2026-09-28）：

| 零件 | 现状 | 出处 |
|---|---|---|
| **AI 护栏（规则引擎/工具白名单）** | 云端成熟（阿里云 AI Guardrails、F5 等），**端侧无开源实现** | 各云厂商产品页 |
| **VLA 运行时监督** | 论文级，2026 年刚定义问题 | arXiv:2604.01723（Runtime Safety Supervision for VLA Driving） |
| **场景化安全包络** | 论文级，提出二维包络需求 | arXiv:2606.14238（Scenario-Specific Safety Envelopes） |
| **确定性安全层** | 极成熟，但不懂 AI 错误模式 | NVIDIA Halos、ISO 26262/ASIL 体系 |
| **端侧执行隔离** | OS 级沙箱够用 | Landlock/seccomp/Seatbelt（第三十一章） |

**集成的端侧监护沙箱：不存在。**

这个状态与 2023 年 Agent 沙箱爆发前夜同构：当时 Firecracker 已成熟五年、容器成熟十年，但"给 Agent 的沙箱平台"无人拼装，直到 E2B 出现。今天：护栏成熟了（云端）、包络成熟了（功能安全）、运行时监督刚有论文（VLA）、执行隔离免费（OS 原生）——**"给不可靠端侧 Agent 的监护沙箱"无人拼装。**

**一个必须诚实交代的约束**：监护型沙箱的"成熟终点"是车规认证（ASIL-D），那是数年与重资金的投入，个人与小团队不可达。但开源项目的价值不需要认证先行：**教育机器人、科研 VLA、服务机器人、消费级 IoT 这些不需要车规的场景，现在就缺这个零件**。合理路径是先吃无需认证的市场，让需要认证的市场来找你——认证是商业化阶段的事，不是立项的前提。

## 七、给立项者的推演（作者自用，亦供参考）

若沿此框架立项，产品定义可以从监护型四问直接导出：

1. **Q1 → 包络 DSL**：用配置声明"什么场景、什么动作、什么数值范围"（参考第二篇论文的场景化思想），而不是硬编码；
2. **Q2 → 累积追踪器**：滑动窗口内的误差积分、漂移检测、超阈值干预——这是与传统 ADAS 包络的差异化核心，也是论文没做的工程空白；
3. **Q3 → 降级状态机**：参考第二十九章状态机四铁律（幂等/单向失败/可重试/可观察），定义"正常 → 降级 → 交还人类"的迁移；
4. **Q4 → 病历式轨迹**：每次拦截/降级产出训练友好的记录（场景、输入、输出、包络边界、分布外判定），让沙箱天然长在训练闭环里。

**定位一句话**：给"必然犯错的智能体"设计的、以错误累积管理为核心的监护层——不是更好的关押型沙箱，是沙箱的另一个物种。

|---|---|

| 立项定位 | 给"必然犯错的智能体"的错误累积管理层；认证是后话，无需认证的市场先行 |

## 思考题（能算账的那种）

1. 一个送餐机器人，导航模型每 100ms 输出一次速度指令，包络限制 ±0.5m/s。假设模型存在系统性偏差：每次输出比正确值大 2%（在包络内）。请计算：执行 10 分钟后机器人的位置漂移量；若走廊宽度 2m、初始居中，多久会撞墙？由此推导"累积追踪器"需要的最小窗口长度与干预阈值。
2. 对比设计：关押型沙箱的审计日志保留策略（合规驱动，保留 N 年）与监护型的轨迹记录策略（训练驱动，按数据价值保留）。两者的存储成本模型有何本质差异？（提示：法律档案 vs 病历——前者全量长存，后者按样本价值采样）
3. 监护型的降级状态机设计：定义"正常→建议模式→强约束模式→交还人类"四级降级的触发条件、迁移的幂等要求、以及为什么"交还人类"必须是单向迁移（不可自动恢复）。（提示：参考第二十九章状态机四铁律）

## 下章预告

监护型沙箱把沙箱的边界从"隔离进程"推到了"隔离错误在时间中的传播"。但还有一个更远的问题：当沙箱同时管着执行、记忆、权限与错误，它和"操作系统"的边界还剩多少——第二十四章的终极之问，在监护型的视角下会有新的答案。
