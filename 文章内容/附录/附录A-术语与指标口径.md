这套文章反复使用“沙箱、启动、内存、并发、可用”等词。如果不先统一口径，不同章节里的数字会看起来互相矛盾。本附录只做阅读和写作时的共同字典，不替代具体章节中的实现分析。

## 一、执行单元

| 术语 | 本系列中的含义 | 不应直接推断的内容 |
|---|---|---|
| 容器 | 以 namespace、cgroup 等机制隔离的进程组，通常共享宿主机内核 | “容器不安全”或“容器一定不够用” |
| VM | 拥有独立 guest 内核、由 Hypervisor 管理的虚拟机 | 所有 VM 都同样重、同样慢 |
| MicroVM | 删除大量传统设备和启动环节的轻量 VM | 只要叫 MicroVM 就天然达到某个延迟 |
| 沙箱 | 面向一次任务或会话的执行边界，包含文件、进程、网络、资源、生命周期和审计语义 | 沙箱一定等于 VM，或一定是一次性销毁 |
| Agent 运行时 | 承载模型循环、工具调用、工作记忆和结果回传的执行环境 | 只提供一个 shell 就完成了 Agent 运行时 |

## 二、速度指标

一篇文章说“启动 60ms”时，必须说明计时起点和终点。建议至少区分：

1. **请求受理延迟**：客户端发出请求到 API 返回任务或沙箱 ID。
2. **实例出生延迟**：磁盘、内存、MicroVM 和网络资源已建立。
3. **环境可用延迟**：guest agent 健康检查通过，可以执行第一条命令。
4. **结果可见延迟**：第一条命令的输出回到客户端。

P50、P95、P99 也必须和样本条件一起报告：节点规格、模板是否命中、并发数、是否跨节点、是否包含网络策略和客户端传输。平均值只能描述中心趋势，不能代替长尾和失败率。

## 三、内存指标

“5MB 增量”应理解为某种额外开销的量级或公开目标，不等于一个沙箱的总内存。容量估算至少分开：

```text
总内存 = guest 工作集 + VMM/设备额外开销 + 网络/日志/缓存 + 宿主预留
```

模板页共享、写时复制和内存过量分配会改变实际结果。第十一章和第二十八章分别从资源账本与测量方法解释这件事。

## 四、并发指标

“并发”至少有四种口径：

- 创建并发：同时处于创建流程中的请求数；
- 运行并发：同时执行 CPU、网络或磁盘工作的沙箱数；
- 驻留并发：仍占用资源但可能正在等待模型下一步的沙箱数；
- 工作流并发：同时运行的父任务及其 worker 拓扑数。

创建吞吐高，不代表驻留容量高；单沙箱启动快，也不代表多租户共享公平。第十七至第十九章应结合这四种口径阅读。

## 五、证据等级

正文中的判断可分为三类：

1. **源码事实**：能在指定版本的代码、配置或测试中定位；
2. **公开指标**：项目 README、官方文档或论文明确给出的数字；
3. **教学推演**：为了说明决策过程而设定的算例，不能当作生产承诺。

读者看到容量、延迟和成本数字时，先判断它属于哪一类，再决定能否迁移到自己的节点、版本和负载。
